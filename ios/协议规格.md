## 4. BLE TBOE 近场协议

### GATT 结构 `[已确认]`

| UUID | 角色 |
|---|---|
| `0000fff1-0000-1000-8000-00805f9b34fb` | 主特征（读写） |
| `0000fff2-0000-1000-8000-00805f9b34fb` | 次特征 |
| `00002902-0000-1000-8000-00805f9b34fb` | CCCD（订阅通知） |

`0000fff1/fff2` 属**厂商自定义透传模组**（非 Nordic UART Service），
说明车端用透传模组承载自定义二进制协议。

### 握手状态机 `[由中文文案还原]`

```
[1] 连接请求写入
      ↓
[2] 等待车端挑战码  ← Challenge(code=...)
      ↓  车端拒绝? → 车端拒绝连接
[3] 挑战码验签（SHA256withECDSA）
      ↓  失败 → 挑战码验签失败
[4] 回送响应 → 连接应答写入
      ↓  重试连接应答（可重试）
[5] 连接应答验签
      ↓  失败 → 连接应答验签失败
[6] 会话建立 → 白名单同步 → 进入可控状态
```

### 全部错误分支 `[已确认，来自文案]`

| 阶段 | 错误文案 |
|---|---|
| 连接 | `连接请求写入失败`、`连接抛异常`、`连接认证失败`、`车端拒绝连接`、`蓝牙连接失败` |
| 挑战码 | `等待车端挑战码`、`挑战码为空`、`挑战码报文没有`、`挑战码报文解析失败`、`挑战码验签失败`、`车端没有下发挑战码` |
| 应答 | `重试连接应答`、`连接应答没有`、`连接应答解析失败`、`连接应答验签失败`、`车端没有回连接应答`、`会话类型不匹配` |
| 白名单 | `白名单同步被车端拒绝`、`白名单同步没有回应`、`取白名单失败`、`缺少白名单且云端取不到` |
| 会话 | `蓝牙会话已断开`、`发送断开请求失败` |
| 帧 | `车端报文分片丢失`、`收到不合法帧`、`定长字段越界`、`响应不是合法`、`报文不被接受`、`连接或订阅通知失败` |

### 会话对象 `[已确认]`

`app.netal.ble.tboe.TboeBleTransport.TboeSession`

日志标签：`NetaTboe`、`NetaTboeLink`、`BleScanCoordinator`

## 5. 加密与证书 `[已确认]`

### 算法

| 用途 | 算法 |
|---|---|
| 密钥材料加密 | `AES128_CTR_HMAC_SHA256` / `AES256_CTR_HMAC_SHA256` |
| AEAD | `AES-GCM` / `AES-EAX` / `AES-SIV` / `AES-GCM-SIV` / `AES-CMAC` |
| 流密码 | `ChaCha20Poly1305` / `XChaCha20Poly1305` |
| 设备/车辆签名 | `SHA256withECDSA` |
| 证书签名 | `SHA256withRSA` |
| 摘要 | SHA-256 |

原实现：Google Tink（`androidx.security:security-crypto:1.1.0-alpha06`）
→ iOS 用 **CryptoKit** + **Security.framework** 替代，无需第三方密码库。

### 证书资产（可直接复用）

| 文件 | 说明 |
|---|---|
| `assets/pki/hozon-ca.pem` | 哪吒根 CA，`CN=HOZON Root CA`，ECDSA P-256，SHA-384，2022-05-24 → 2052-05-16 |
| `assets/pki/preset.crt.pem` | 预置演示证书 `CN=Preset-demo`（`O=HOZON_CA, OU=Preset`），2022-06-04 → 2032-06-01 |
| `assets/pki/preset.key.pem` | ⚠️ 上述证书的 RSA-2048 私钥明文 |

### 证书签发流程 `[已确认]`

```
1. 本地生成设备密钥对（ECC）
2. 上传公钥 mobilePubkey → 云端
3. POST /pivot/security-api/pki/cert/1.0/applyCert 申请设备证书
4. 云端下发证书 → 组装 X.509 链（用 hozon-ca.pem 验签）
5. 申请车主钥匙 → 车端下载钥匙原文
6. 车端返回 vehiclePubkey → 与本地密钥材料比对校验
7. 激活钥匙
```

字段：`certificatePem`、`privateKeyPem`、`publicKeyPem`、`eccPubkey`、
`mobilePubkey`、`vehiclePubkey`、`keyDataVer`、`keyId`、`keyVersion`、`keyStatus`、`keyType`

文案佐证：`申请设备证书失败`、`设备证书组装失败`、`客户端证书资产为空`、
`车控将缺少客户端证书`、`上传公钥成功/失败`、`下载钥匙原文成功/失败`、
`车端公钥与钥匙材料不匹配`、`申请车主钥匙成功/失败`、`激活钥匙失败`、`蓝牙钥匙已过期`

### iOS 实现注意

- `privateKeyPem` 需存 Keychain（`kSecAttrAccessibleAfterFirstUnlock`），**不可放 UserDefaults**
- P-256 ECDSA 用 `SecKeyCreateSignature`（`.ecdsaSignatureMessageX962SHA256`）
- 证书链校验用 `SecTrustEvaluateWithError` + 自定义 anchor（hozon-ca.pem）

## 6. 靠近自动解锁 `[已确认]`

### 数据模型（DEX 明文）

```
BleProximityMeasurement(averageRssi=...)
BleProximityPolicy(enterThresholdDbm=...)
NotificationSnapshot(isBluetoothConnected=...)
```

### 流程

1. 后台周期扫描 BLE
2. 滑动平均 RSSI（`averageRssi`）
3. 与 `enterThresholdDbm` 比较
4. 距离判定 → 触发解锁
5. 起扫前复核（防抖）
6. 状态栏通知展示（iOS 无状态栏通知 → 用 Live Activity 或本地通知替代）

### ⚠️ iOS 最大风险

iOS 对 BLE 后台扫描限制极严：

- `allowsBackgroundUpdates` 在 iOS 17+ 默认关闭
- 后台持续扫描会被系统挂起，**无法实现「始终在线的靠近解锁」**
- 现实可行的替代方案：
  - **地理围栏（Geofence）** 到达车辆位置后启动扫描
  - **CarPlay + 数字钥匙**（需车机支持）
  - **短时高优先级扫描**：进入地理围栏后扫描若干秒

Android 上 `ProximityUnlockService` 是常驻前台服务 + `BOOT_COMPLETED` 自启，
这套模型在 iOS 上**不存在**。这是移植中最需要重新设计的部分。

## 7. 车控通道策略 `[已确认]`

| 模式 | 行为 | 文案 |
|---|---|---|
| 自动（默认） | 蓝牙已连接优先 BLE，失败/未连接回退网络 | `蓝牙已连接时优先使用`、`未连接或下发失败时走网络` |
| 仅蓝牙 | 不发网络请求 | `已按设置只走蓝牙`、`不发网络请求` |
| 仅网络 | 只经服务端下发 | `该动作仅支持网络通道`、`只能走网络` |

注意：并非所有指令都有近场实现 → `该动作没有近场命令`、`只支持网络的动作仍走网络`。

存储键：`controlChannel`、`control_channel`、`controlChannelStore`
